# Debug 记录

每条一行：现象 + 根因 + 改法。

- OSS 生命周期"历史版本"选项文案与阿里云实际 UI 不符，属文档措辞问题，功能等价
- OSS `CORS_OR_NETWORK`：跨域规则"允许 Headers"必须填 `*` 不能留空，否则预检被拒
- OSS `AccessDenied`：新建 RAM 用户后漏了"添加权限"一步，策略建了但没挂到用户身上
- 词卡里出现未渲染的墨墨标记黑块（如 `[T#!!fedcb6#het-woord]`）：单词 JSON 接口误用了整句卡片专用的高亮规则，已收紧 prompt 并加 `unmark()` 兜底剥离
- 备份时间显示「1970/1/4」：`lastBackup | 0` 位运算把毫秒时间戳截成 32 位整数，改用 `Math.max(0, Number(...) || 0)`
- 分词把两个词并成一个（只查得到前一个）、甚至整句只给一个 token：改为不信任模型切分，用 `fixToks()` 按原句本地校准（空格为硬边界，藏语按音节点、日语按字种兜底）
- 在单词查询里改藏语注音/录音后关掉词卡会跳到句子阅读：藏语面板无条件调了 `paintRead()`，改成按栈顶实际页面重画的 `refreshUnderSheet()`
- 「删除已添加」看着没反应、删掉的卡片过几秒又回来：云端合并没有「删除」概念，同步是 GET→merge→PUT，本地没有的一律当成对方新增而复活；改为记删除墓碑，并让勾选「已添加」时更新 `ts`
- 背单词 勾一个词、另一个自己也被勾上：熟知记录用「有没有这个键」表示，取消就是删键，而云端按并集合并——本地取消掉的词下次同步被远端原样加回来；改成带符号时间戳（正=熟知，负=明确取消），按绝对值大的一方胜
- 卡片顺序会在同步后乱跳：云端合并按 `ts` 排序，而 `ts` 是「最后修改时间」，勾一下「已添加」就跳到最前；改成独立的排序键 `pos`，「移到最后」也靠它
- 发音总是系统默认的荷兰语男声：代码从音色列表里挑第一个语言对得上的硬塞给朗读，盖掉了系统设置；改为默认只设语言，另加按语言点名音色（iOS 26 起系统不再把「朗读内容」里的选择告诉第三方）
- 卡片库「查看详解」显示带标记的原文：改为渲染后的卡面，`renderCodes()` 补齐加粗/下划线/斜体/删除线/上下标/段落标题等全部墨墨样式
- 卡片库重做为 App 内复习：`S.cards` 变成轻量索引（原文/语言/时间/排序/正文版本 `bv`），翻译+详解+追问详解（`{d, n, bv}`）按卡存成云端 `cards/<id>.json`，展开时才取，本机只留最近 30 张已上传的；老版本内联在 `detail` 里的正文（本机、云端 data.json、老备份）会自动搬进新存储。同时去掉「已添加」勾选、「复制全部」和卡片上限；追问不再喂给详解 prompt，而是原样进「追问详解」栏，保存前可编辑
- 背单词里单个词「生成卡片」，词卡里追问的答案没出现在「追问详解」：`genWordCard` 从不接收追问，词表里点词的追问（上下文=词本身）被丢掉；现在由 `wordQaFor(k,[词],true)` 收集后原样作为 notes 传给编辑页

- 卡片背面改版：句子卡的详解（墨墨格式）又长又细，却占着卡片库和预览页的主位置。现在正文多一个 `b`（简洁背面：整句翻译 + 每词释义变位，由 `briefPrompt` 取 JSON、`briefText` 本地拼，与详解并行生成），页面顺序为 卡片背面 → 追问详解（含词卡里「展开详解」的单词解析，`wordDetailsFor`）→ 折叠的墨墨格式；老卡没有 `b`，背面留空。同步、备份、云端 `cards/<id>.json` 都带上 `b`
- 新增跟读录音（`05c_rec.js`）：所有句子都能录音回放，和标准发音对比。录音只放内存（blob URL），不落盘不上云不进卡片；各模块重画时 `recSweep` 清掉已退不回去的句子（重新生成、挤出历史、换语言），卡片库的录音在 `render()` 离开库时整组丢弃。按钮用 document 捕获阶段统一接管点击，否则卡片库行内按钮会冒泡成「展开卡片」
